# The modes libtsm recognises

Generated by `test/gen-modes.c` from `src/tsm/tsm-modes.def` (ADR-201 in aaronsb/kmscon); `make modes` rewrites this page and `modes.tsv`, and the `modes-doc` test fails when either differs from the table. Edit the table, not this page.

33 modes: 26 supported, 0 partial, 3 ignored, 4 refused.

- **Status.** Supported: set and reset do what the spec says. Partial: part of it, and the spec column names the issue for the rest. Ignored: accepted with no effect; the spec column says why, or names the issue for an effect that is wanted. Refused: deliberately not implemented; the spec column says why.
- **DECRQM.** The reply to `CSI ? Ps $ p` (DEC) or `CSI Ps $ p` (ANSI), as `tsm_vte_get_mode` also gives it: 1 set, 2 reset, 3 permanently set, 4 permanently reset. "At start" is a new vte with libtsm's default settings; "1 or 2" means both were seen after the mode's SM and RM, and under a steady cursor; a single value is the only one seen. "Once the host offers it": the host's setting that says it does what the mode needs is on: `tsm_vte_set_sync` for mode 2026, until which SM does nothing; sixel turned on with an image budget for 80, 1070 and 8452, whose SM and RM are stored meanwhile. Until then the mode replies its fixed state. A number with no row replies 0, not recognised, and SM and RM log it at debug level.
- **Reset.** Which resets restore the default: soft (DECSTR and RIS), hard (RIS only), or none. For an ignored or refused row, which resets restore its legacy bit in `tsm_vte_get_flags`.
- **Host.** What the program embedding libtsm must do for the mode to work: input (report pointer or focus events, or stop repeating a held key), paste (paste through `tsm_vte_paste`), draw (present frames by the mode), sixel (turn sixel on and give the screen an image budget), or none.
- **Terminfo.** The capabilities whose strings set or reset the mode.
- **Tests.** The unit tests (`START_TEST` names) and tier 1 cases that set and reset the mode.
